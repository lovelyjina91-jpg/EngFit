# 영핏 학생 누적 학습 기록 시스템

학생이 푼 모든 퀴즈·클리닉·테스트 결과를 **학생별로 쌓고**, Claude가 **강점·약점·발전 과정·오답 개선 여부**를 계속 분석하는 시스템이에요.

> ⚠️ 이 저장소는 **공개**(GitHub Pages)예요. 학생 명단, 전화번호, 점수 같은 **학생 데이터는 절대 여기에 올리지 않아요.**
> 학생 데이터는 노션(비공개)과 구글 드라이브(비공개)에만 있어요. 이 폴더에는 도구(코드)와 설명서만 있어요.

---

## 1. 전체 흐름 (한 장 요약)

```
학생이 퀴즈 풂 (GitHub Pages)
      │  결과 자동 전송 (기존 방식 그대로)
      ▼
구글시트 「영핏 결과기록」 ── 원본 창고 (지우지 않음)
      │  매일 밤 Claude가 읽어옴
      ▼
records/tools/engfit_records.py ── 이름 정리 → 학생 ID 연결 → 개념 분류 → 분석
      │
      ▼
노션 「원생 관리」
  ├─ 학생 리스트        : 학생 ID, 퀴즈코드, 별칭
  ├─ 📊 학습 기록 (누적) : 제출 1건 = 1줄
  ├─ 🧩 강점·약점 추적   : 학생 × 개념별 상태 (취약/개선중/극복/강점)
  ├─ 📈 학생 분석 리포트  : 학생별 종합 분석
  └─ 📝 테스트 요청      : "지금 테스트 만들어 주세요" 요청함
      │
      ▼
구글 드라이브 「영핏 학습기록 백업」 ── 매주 백업본
```

## 2. 학생 ID 규칙

- 형식: **`입학연도-이름`** (예: `2026-김영광`)
- 입학연도는 MakeEdu의 **입학일** 연도예요. 한 번 정하면 바뀌지 않아요.
- 이름이 같은 학생이 들어오면 뒤에 번호를 붙여요: `2026-김영광-2`
- 새 학생이 오면 노션 「학생 리스트」에 한 줄 추가하고 `학생 ID`, `퀴즈코드`를 채워요. (Claude에게 "새 학생 ○○ 등록해줘"라고 해도 돼요.)

### 퀴즈코드와 별칭이 필요한 이유
학생들이 퀴즈에 이름을 제각각 입력해요 ("Lee", "하은이", "1", "ㅇ" 등).
Claude는 이렇게 연결해요.
1. 입력한 이름이 **이름**이나 **별칭**과 같으면 → 그 학생
2. 아니면 퀴즈ID 안의 **퀴즈코드**(예: `clinic-kdy-0808` 의 `kdy`)로 추정 → `확인 필요` 체크
3. 둘 다 안 되면 → 학생 없이 저장하고 `확인 필요` 체크

`확인 필요`가 체크된 기록은 가끔 확인해서 학생을 바로잡아 주세요.

## 3. 분석은 어떻게 하나요?

| 항목 | 계산 방법 |
|---|---|
| 프로젝트 | 퀴즈ID 앞부분으로 분류 (`clinic-` 오답클리닉, `basic-` 기초클리닉, `concept-` 개념확인, `vocab`/`daily-` 단어시험, 내신·기말 → 내신대비 등) |
| 개념 | 퀴즈 제목의 개념 이름(예: "to부정사", "현재완료")으로 분류. 제목에 개념이 없는 클리닉은 원본 퀴즈의 개념을 물려받음 |
| 강점·약점 | 개념별 최근 3번 정답률: 85% 이상 **강점**, 65% 미만 **취약**, 그 사이 **개선중**. 처음엔 70% 미만이었다가 85% 이상이 되면 **극복** |
| 발전 추세 | 기록을 앞쪽 절반·뒤쪽 절반으로 나눠 평균 비교 (5%p 이상 차이 → 상승/하락) |
| 오답 개선율 | 클리닉·재도전에서 맞힌 문항 비율 (문항 수 5개 이상일 때만) |
| 찍기 의심 | 문항당 3초 미만으로 풀었는데 정답률 50% 미만 |
| 중복 전송 | 점수·틀린문항·소요시간이 똑같은 결과가 다시 전송되면 중복으로 보고 분석에서 뺌 |

## 4. 더 정확한 분석을 위한 퀴즈 제작 규칙 (앞으로 만드는 퀴즈)

기존 전송 코드(`engfit-quiz-results` 스킬)는 **그대로** 써요. 아래만 지켜 주면 분석이 훨씬 정확해져요.

1. **quizId**: `<종류>-<학생코드>-<MMDD>-p<영역번호>` (예: `clinic-kyk-0923-p1`)
   - 학생코드는 노션 「학생 리스트」의 `퀴즈코드` 첫 번째 값을 써요.
2. **quizTitle**: `학생이름 + 개념 이름 + 날짜` (예: `김영광 to부정사 오답 클리닉 9/23`)
3. **detail 문항마다 `tag`(개념 이름)를 넣기** — Apps Script는 고치지 않아도 돼요.
   ```js
   detail.push({ no: 3, ok: false, chosen: "seen", answer: "seeing", tag: "동명사" });
   ```
   `tag`가 있으면 문항 하나하나를 개념별로 집계해서, 한 퀴즈에 여러 개념이 섞여 있어도 정확하게 강점·약점을 나눠요.
   개념 이름은 `tools/engfit_records.py`의 `CONCEPTS` 목록에 있는 이름을 쓰면 가장 좋아요.
4. 오답 클리닉을 만들 때는 원본 퀴즈ID를 `<원본ID>-clinic`처럼 이어 붙이면 "오답이 고쳐졌는지"를 자동으로 비교해요.

## 5. 테스트지 즉석 생성

- **선생님**: Claude에게 "김영광 약점으로 테스트 만들어줘"라고 말하면 돼요.
- **학생/선생님 (노션)**: 「📝 테스트 요청」에 한 줄 추가 (학생, 범위, 세부 내용). Claude가 수업 시간대(15~22시)에 1시간마다 확인해서 퀴즈를 만들고 `퀴즈 링크`를 채워요.
- 만들어진 퀴즈는 기존 표준(자동 전송 포함)을 따르므로, 풀면 결과가 다시 학습 기록으로 들어와서 **분석 → 테스트 → 풀이 → 재분석**이 계속 돌아가요.

## 6. 데이터 손실 방지

| 지키는 방법 | 설명 |
|---|---|
| 원본은 구글시트 | 퀴즈 결과는 먼저 구글시트에 쌓여요. 구글시트는 **버전 기록**(파일 → 버전 기록)으로 예전 상태를 되살릴 수 있어요. |
| 노션 사본 | 노션 기록은 `고유키`(제출시각\|퀴즈ID\|입력이름)로 중복 없이 쌓여요. 지워져도 구글시트에서 다시 만들 수 있어요. 노션 휴지통은 30일 보관돼요. |
| 매주 백업 | 매주 일요일에 구글 드라이브 「영핏 학습기록 백업」 폴더에 전체 기록 사본을 만들어요. |
| 공개 저장소 보호 | 학생 데이터 파일은 `.gitignore`로 막아서 실수로 GitHub에 올라가지 않게 해요. |
| 권장 | 노션 「📊 학습 기록」 데이터베이스는 오른쪽 위 `···` → **데이터베이스 잠금**을 켜 두면 실수로 고치는 일을 막을 수 있어요. |

## 7. 도구 사용법 (Claude용)

```bash
# 1) 구글시트 내용(드라이브 읽기 결과)과 노션 학생 명단(JSON)으로 기록 정리
python3 records/tools/engfit_records.py normalize SHEET.txt ROSTER.json records.json
# 2) 학생별 분석
python3 records/tools/engfit_records.py analyze records.json analysis.json
```
입력·출력 파일은 반드시 **저장소 밖**(스크래치 폴더)에 둬요. 자동 실행 절차는 [`RUNBOOK.md`](RUNBOOK.md)에 있어요.
